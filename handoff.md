**Slice 4 settled the threshold open point, provisionally, and said so.** The measure is a normalized Levenshtein ratio, `1 - distance / max(len)`, over text case folded with whitespace and every punctuation mark but the decimal point stripped, and the threshold is `MATCH_THRESHOLD` at 0.72 in `lib/highlight-match.ts`. The spec's own open point asked for the 40 labelled fixtures, which are slice 9, so the delta records 0.72 as a judgment with its two boundary cases unit-tested rather than as a measurement. Whoever runs slice 9 changes one line and reruns those tests. The decimal point survives normalization because "4200" and "42.00" are different amounts and the measure may not treat them as one.

**A candidate never spans two text lines.** A receipt prints a label and its amount at the two ends of one line, so clustering boxes by vertical midpoint pulls in the line above and matches the wrong words. The matcher takes tesseract's own line structure and scores runs within one line, capped at the `sourceText` token count plus two, and `readTextLines` falls back to grouping by midpoint only when the recognize output carries no structure at all.

**The OCR pass runs beside the model call, from the same press.** Measuring on file choice spends a visitor's battery on a file they may never submit, and measuring after the fields land reads as a second request the visitor is waiting on. The workspace holds the OCR phase (`idle`, `measuring`, `ready`, `failed`) separately from the extraction phase rather than widening that union, because the two progress independently and one union would need a state per pair.

**The region map is derived, never stored.** A `useMemo` over the receipt and the measured lines rebuilds the whole map, which is why a line item add or remove needs no index remapping. The edited list and the standing refusals both go through `remapAddressOnRemove`; the regions deliberately do not, because deriving them from the receipt that now exists cannot get the shift wrong. The cost is a few thousand Levenshtein calls on short strings per rebuild, well inside a frame.

**The overlay is positioned in percentages, so nothing listens for a resize.** The mark is one absolutely positioned element inside a wrapper around the `img`, with its four offsets written as percentages of the natural pixel size, and the browser rescales it with the image for free. There is no `ResizeObserver`, no `getBoundingClientRect` and no second OCR pass when the pane narrows, and anyone adding one should ask first why the percentages stopped being enough. `.preview` lost its `max-height` and its `object-fit` in the same change: with a clamped height the element box stops matching the rendered image and every percentage drifts.

**An absent mark is worded two ways, because it has two causes.** A field whose `sourceText` is null reads "The receipt printed no value here, so there is nothing on the image to mark." A field whose `sourceText` matched nothing above the threshold reads "The app could not find this text on the image, so it marked no region." The second is the honest-failure case the whole matched-never-generated approach exists to produce, and it reads as an answer rather than as a pane that failed to draw only because it is worded differently from the first.

**Slice 5 settled the scanned-PDF open point by rasterizing and reusing the OCR pass.** The spec's own alternative, showing no highlight for a page with no text layer, would have shipped one of slice 7's three samples with highlighting that silently never works. A page with no usable word at all goes through the tesseract pass slice 4 built, which takes the rasterized blob unchanged. A thin text layer is still the answer: six words with exact coordinates are six real words, and the matcher already returns nothing rather than something wrong for the fields they do not cover. There is deliberately no word-count threshold, and anyone adding one should say what it buys over that.

**The browser rasterizes, so the route's contract is images.** pdf.js is a browser library, and running it on the Node runtime means a canvas polyfill and a wasm build on a serverless function for a conversion the page can do with the DOM it already has. Three things fall out of doing it client-side: the preview is the bitmap the model read, the word boxes share one pixel basis with that preview, and the route keeps one code path over image bytes. The cost is that `/api/extract` no longer accepts `application/pdf`, which nothing outside this app calls. The limits spec now states the picker's four types and the route's three as two separate checks rather than pretending they are one.

**`not_jpeg` is now `unsupported_type`.** A code naming one format was wrong the moment three more arrived, and keeping it for a PNG refusal would have put a lie in the response body. The code is a union type, so TypeScript found every site. The route's message names all four types a visitor can pick, because a visitor who picked a PDF through the page never sees this message at all.

**A PDF page is rasterized at twice its CSS size, capped at the same 2000 pixels the OCR downscale uses, as PNG.** A page at scale 1 is 72 dots per inch, too coarse for the model to read small print and too coarse for OCR on a scan. Doubling gives roughly 144, and `OCR_LONG_EDGE` is imported rather than written again so one cap serves both. PNG rather than JPEG because a scanned receipt's thin strokes are exactly what the model and tesseract have to read, and JPEG's ringing is worst there. The trade is a larger request body, which is slice 7's problem to size.

**The text layer's coordinates come off pdf.js's own viewport transform.** `lib/pdf-page.ts` multiplies the viewport transform by each item's transform, the same product pdf.js computes for its own text layer, rather than rebuilding the bottom-left-to-top-left flip from a scale and a page height. The matrix also carries page rotation and a non-zero viewBox origin, which a scanned invoice can have. A text item holding several words is split proportionally by character count, which is approximate and said to be in the module, because the matcher scores runs of adjacent words rather than whole items.

**The word box source is the page's decision and the matcher never learns it.** `readFirstPage` returns the same `Measurement` shape `createOcrPass` returns, the workspace picks which arrived, and `lib/highlight-match.ts` changed by not one line. Anything that made the matcher branch on the source would put format knowledge in the one module with no business holding it.

**Slice 6 settled the CSV shape open point: one row per line item.** The receipt's own fields repeat on every row, which is what lets a spreadsheet group or pivot on any of them. A receipt that itemized nothing still gets one row with its item columns empty, and a null field is an empty cell for the same reason a null never renders as 0 in the panel: an empty cell says the receipt printed nothing where a zero claims it printed something worth nothing. One row per receipt was rejected because it drops the line items the app works hardest to extract, and two joined files were rejected because the visitor would have to join them.

**The column names carry their level, and the order is a property of one list.** `lib/receipt-csv.ts` holds an array of column definitions rather than a template, so the order cannot drift with whoever edits next. The receipt's fields read as snake case (`merchant`, `merchant_address`, `date`, `time`, `currency`, `subtotal`, `tip`, `total`, `payment_method`, `card_last4`), the taxes flatten to numbered `tax_n_label` and `tax_n_amount` pairs, and the item columns are prefixed `item_`. A reader who sees `amount` alone cannot tell a line from a receipt, which is the mistake the prefix prevents.

**The single export is the batch export over a list of one.** `receiptsToCsv` takes a list and sizes the tax columns to the widest receipt in it, so one header serves every receipt in a file and the two shapes cannot drift apart. The batch JSON envelope is `{ receipts: [...] }` with each entry the single envelope verbatim, carrying no count (it would restate `receipts.length`) and no timestamp (two exports of identical data would then differ byte for byte).

**A CSV carries no confidence and no source text.** Thirty-odd fields each gaining two siblings would triple the width of a row a visitor opened to read amounts. The JSON export already carries both, the control beside the CSV says so, and quoting stays minimal: a comma, a double quote or a newline forces quotes, an inner quote doubles, and nothing adds a leading apostrophe, a thousands separator or a currency symbol, because a file that adds a symbol has changed the value. Rows end CRLF, which is what the format specifies.

**The session key lives in `sessionStorage` and the records live in IndexedDB.** `sessionStorage` is per tab and dies with the tab, which is the lifetime the spec asks for, while IndexedDB is per origin and outlives it. One database (`ai-receipt-scanner`, store `receipts`, indexed by `sessionId`) holds every session's records and lists only this one's. A database named after the session would leave an unbounded pile nothing ever opens again. Nothing sweeps the orphans, because deleting a visitor's data unasked is what this repo does not do, and nothing caps the count, because slice 7 owns the 40-per-session cap and must not find a different number already enforced.

**A stored record is six keys and no more.** `id`, `sessionId`, `savedAt`, `receipt`, `warnings`, `edited`. The id and the timestamp never reach the receipt object, for the same reason the line item row keys do not: they are facts about this browser, not about the receipt, and the Zod schema governs what sits inside. No upload bytes and no image reach the store, which is tested.

**The record is written on every edit, not only on extraction.** That is what makes a correction survive a reload, and it is why `rememberOpen` keeps the original `savedAt`: correcting the oldest receipt should not move it to the top of the list. The put is fire-and-forget against the render, so a store that refuses logs once and leaves the receipt on screen working.

**A reopened receipt has no image, and that is a different sentence from a failed match.** The app stores no upload, so there is nothing to show and nothing to measure, and the pane says so in its own words rather than reusing the slice 4 wording about text the matcher could not find. A refused upload is not stored at all, because it fills no column the table lists.

## 4. Decisions already made

- **One model call per receipt.** The image goes to the model with Structured Outputs on the Responses API, `text: { format: zodTextFormat(modelReceiptSchema, "receipt") }`, whose schema is the field set. The Chat Completions spelling, `response_format: { type: "json_schema", strict: true }`, is what this line used to say and is not what `lib/extract-receipt.ts` calls. No JSON parsing out of prose, no retry loop around a malformed response. Zod validates the parsed object again on the server.
- **Confidence comes from the model.** Each field carries a sibling `confidence` (0 to 1) and a `sourceText` holding the characters the value was read from. Anything under 0.8 is flagged for review.
- **Highlighting is matched, never generated.** The model does not return coordinates, and asking it to would produce numbers that look precise and are not. The app gets word boxes from the document (pdf.js text layer, or tesseract.js for images), then fuzzy-matches each field's `sourceText` against those words. No match clearing the threshold means no highlight, rather than a wrong one.
- **Arithmetic is checked in code.** Line items sum to the subtotal; subtotal plus taxes plus tip equals the total. A mismatch is a warning naming the difference, on both fields involved. The app never rewrites a number to make the math close.
- **"Not a receipt" is a first-class answer.** The response schema carries `isReceipt` and `reason`. False means show the reason and stop.
- **Money is a decimal string, never a float.**
- **The decimal arithmetic is written in this repo, over scaled `BigInt`.** `lib/decimal.ts` parses a decimal string into a signed `BigInt` of its digits plus a scale, then lifts both operands to the wider scale before it adds, subtracts or compares. Slice 2 chose that over `decimal.js` and `big.js` because the app's contract is strings at both ends, so a library still needs a parse step and a render step beside it, and none of its multiply, divide or rounding-mode surface is wanted. Integer cents was rejected too: `DECIMAL_PATTERN` admits a third decimal place, and rounding a value to run a check is the thing the checks exist to catch. `big.js` stays the obvious replacement behind the same function names if a later slice needs multiplication for a per-item check.
- **Nothing is stored.** Uploads live in memory for the length of the request. Results live in the browser. The only server-side state is rate-limit counters. This is stated on the page next to the drop zone, not buried in About.
- **Currency is inferred from the symbol and locale**, never silently defaulted to USD.
- **Delegate the building to background agents.** Bob wants to keep talking while the work happens, so implementation runs in subagents rather than inline on the main thread. One agent per slice, or per independent piece of a slice, launched together in a single message when the pieces do not depend on each other. Report what came back; do not make him wait on a tool call to ask a question. This overrides the harness default of not spawning agents unasked, and it was asked for on 2026-10-01.
- **Agents do most of the development, in vertical slices.** Each OpenSpec change is one thin path through every layer rather than one layer across every feature: upload, model call, validation, form, export, deployed and working before the next slice starts. The first slice is a walking skeleton (a single JPEG to the flat fields to a JSON download, live on Vercel), and every slice after it widens that path. No slice is finished until it runs end to end in the deployed app, which is what makes the work checkable without a human reading the diff.
- **All eight open points are now settled.** Slice 1 answered the Zod-failure point, slice 2 answered two more, slice 4 settled the highlight match threshold and similarity measure provisionally, slice 5 settled the scanned PDF with no text layer, slice 6 settled the CSV shape, and slice 7 settled the per-IP window and the session cap. `grep -c "Open point" openspec/specs/*/spec.md` is what confirms the count, and it should read zero everywhere once slice 7 is archived.
- **Eight open points were deliberately unresolved at the start.** The capability specs mark each with an `**Open point:**` line, and Bob decided on 2026-10-01 to let the slice that needs an answer settle it rather than deciding all eight up front. They are: the highlight match threshold and similarity measure; whether a scanned PDF with no text layer gets rasterized and OCR'd or simply shows no highlight; whether arithmetic comparison is exact or carries a cent of tolerance; whether empty `lineItems` is itself a flag; the CSV shape, meaning one row per receipt or per line item and how taxes flatten; whether the per-IP window is fixed or rolling and what the rejection tells the visitor; what keys the 40-per-session cap and whether it resets; and what the visitor sees when server-side Zod validation fails. Whichever slice answers one records the answer in that spec through the normal `/opsx:` loop.
- **The slice order is the order of risk, not of layers.** Highlighting and the accuracy fixtures come after editing and arithmetic, because they are the parts most likely to need rework, and rework on top of a working path costs less than rework on top of a half-built layer. Section 9 lists everything outstanding as an inventory; `tasks.md` carries the slice order.
- **The work runs through OpenSpec**, already initialized. Run it with `npx @fission-ai/openspec@latest` rather than a global install. The loop is `/opsx:explore` to think an idea through, `/opsx:propose` to draft the change and its spec deltas, `/opsx:apply` to implement against the plan, `/opsx:archive` to fold the finished change back into the main specs. Needs Node 20.19 or higher; this machine has Node 24.19.0. Six more workflows (`new`, `continue`, `ff`, `bulk-archive`, `verify`, `onboard`) are available behind `openspec config profile` and are not installed.
- **`ai-receipt-scanner-spec.md` stays the product spec.** OpenSpec's `openspec/specs/` holds the capability specs derived from it, one per capability rather than one long document. When the two disagree, fix the product spec in the same change rather than letting the delta carry the correction alone.

Slice 3 kept every rule an edit follows in `lib/field-edit.ts` for that reason, and the panel stays a thin shell. Adding jsdom and `@testing-library/react` is what would move those paths into the suite.
- ~~**The product spec's section 5 promises a reload keeps the session table, and slice 3 does not.** Nothing in the spec is wrong: IndexedDB is slice 6, and until it lands the receipt and its edits both die with the page. Slice 6 is the change that reconciles the two, and the panel states the slice 3 lifetime beside the download in the meantime.~~ **Fixed** in slice 6. The session table is in IndexedDB, a reload keeps it, and the copy beside the picker and the download now says the receipts end when the visitor closes the tab.

- **The tesseract assets are self-hosted, and only the language data is in git.** `scripts/copy-tesseract-assets.mjs` copies `worker.min.js` and all six `tesseract-core*.wasm.js` variants out of `node_modules` into `public/tesseract/` on every `predev` and `prebuild`, because the worker picks a core by name at runtime from the directory `corePath` names and any of the six can be the one it asks for. Those seven files are gitignored and about 25 MB; `eng.traineddata.gz` beside them is committed at 1.88 MB. The `tessdata_fast` repo publishes the language data uncompressed only, so the committed file was gzipped locally from the 4.1 MB raw download. `eslint.config.mjs` ignores `public/tesseract/**`, without which the minified vendor files report over two thousand problems.

- **`createWorker` swallows a failed language fetch and leaves its promise pending forever.** `node_modules/tesseract.js/src/createWorker.js` ends its load chain in `.catch(() => {})`, so a blocked `eng.traineddata.gz` never rejects and the workspace sits on "Measuring the image" until the visitor gives up. `bootWorker` in `lib/word-boxes.ts` races the boot against the library's own `errorHandler` option, which is what turns that hang into the `failed` phase in under a second. The race abandons tesseract's promise, so a half-booted worker thread leaks one per failed boot, which is the trade taken over a timeout that would have to guess how long a slow phone is allowed. Anyone upgrading tesseract.js should check whether that empty catch is still there.

- **The language data is not cached in the browser.** `cacheMethod: "none"` keeps the 1.88 MB file out of IndexedDB, so it is fetched per session. That is a deliberate reading of the nothing-is-stored rule, and it sits beside slice 6's session table, which is the one thing this app does write to browser storage. A later slice that wants the cache back has to say why the two are different.

- **The OCR pass downscales to a 2000-pixel long edge, and that is a different scale from slice 7's.** `OCR_LONG_EDGE` in `lib/word-boxes.ts` exists because tesseract's cost climbs with the pixel count and a phone photograph runs 3000 pixels or more, so an unscaled pass can take most of a minute. Every box is multiplied back into the image's natural pixels before it leaves the module, using the canvas size actually allocated rather than the requested one, because `OffscreenCanvas` holds whole pixels. Slice 7's client-side downscaling answers Vercel's 4.5 MB body cap and changes the bytes the model sees; this one changes neither.

- **Focus is the selection, which means the focus ring now carries two jobs.** A cell's `onFocus` is both the click path and the keyboard path, so one handler satisfies both of the spec's scenarios, and `components/FieldPanel.module.css` draws the ring that tells a visitor which field the mark belongs to. Anything that moves focus programmatically now also moves the mark.

- **A PDF page renders black unless the canvas is filled white first.** A PDF paints no background, so a transparent canvas flattens to black on black in the PNG and both the model and tesseract read nothing. `lib/pdf-page.ts` fills `#ffffff` before it renders, and that one line is why a rasterized receipt is legible at all.

- **pdf.js preserves only `name` across the worker boundary, so error detection reads that.** `BaseException.prototype` is `new Error()`, which means `instanceof PasswordException` is false on the main thread, and `wrapReason` rebuilds a worker-side exception by switching on `ex.name`. `pdfOpenFailureReason` in `lib/pdf-page.ts` branches on the name for that reason. Anyone upgrading pdfjs-dist should check whether that still holds.

- **The route takes three types and the picker takes four, and that is deliberate.** `ACCEPTED_IMAGE_TYPES` in `lib/extract-receipt.ts` holds the three image types; `PICKER_ACCEPT` in `components/ReceiptWorkspace.tsx` writes out all four. The workspace writes its own copy rather than importing the constant, because `lib/extract-receipt.ts` imports the OpenAI SDK and a client import would pull it into the browser bundle. The two lists have to be changed together, and the refusal message names the four either way.

- **Two vendor asset sets are copied now, through one helper.** `scripts/copy-vendor-assets.mjs` holds the mkdir-and-copy, and `scripts/copy-tesseract-assets.mjs` and `scripts/copy-pdfjs-assets.mjs` each declare their own files and call it. Both run on `predev` and `prebuild`. `public/pdfjs/pdf.worker.min.mjs` is 1.2 MB and gitignored; `eslint.config.mjs` ignores `public/pdfjs/**` as well, without which lint reported over fifteen hundred problems from the minified worker.

- **pdf.js logs a `standardFontDataUrl` warning and renders anyway.** A page using a standard font such as Helvetica asks for font data the app does not serve, and the rasterize still came out correct in the browser. The font and cmap directories stay out of `public/` until a sample proves otherwise, at which point they are copied the same way the worker is.

- **Nothing caps the session table, deliberately.** `lib/session-store.ts` has no delete, no sweep and no count limit, because slice 7 owns the 40-per-session cap and finding a different number already enforced here would be worse than finding none. Whoever builds slice 7 adds the cap in one place and decides there what happens at the limit.

- **A store that refuses never throws into a render.** `putReceipt` resolves false, `listSessionReceipts` resolves empty and `getReceipt` resolves null, each logging once per page rather than once per call. A private window, cleared site data or a browser blocking site data makes `sessionStorage` throw on access rather than return null, so every read and write of it is wrapped too. The app then runs exactly as it did before slice 6, with one receipt on screen and no list.

- **The CSV row terminator is CRLF, including after the last row.** `CSV_ROW_TERMINATOR` in `lib/receipt-csv.ts` is what a test reads, so changing it changes one constant. A newline inside a cell is left alone and survives inside its quotes exactly as the receipt held it.

- **An edit keeps the record's `savedAt`.** The session list is in scan order, not last-touched order, so correcting the oldest receipt leaves it at the bottom where the visitor left it. `rememberOpen` in the workspace is what preserves it, and anything that writes a record has to decide the same way.

- **The limiter reads `KV_REST_API_URL` and `KV_REST_API_TOKEN`, not the `UPSTASH_` names.** The Vercel marketplace integration for Upstash for Redis (database `upstash-kv-red-drawer`, connected to all three environments) writes the `KV_` names, so `Redis.fromEnv()` would find nothing and `lib/rate-limit.ts` constructs the client explicitly. Both variables are in Vercel and in `.env.local`, and `.env.example` lists them with placeholders.

- **Three failure modes of the limiter are deliberately different.** An unreachable store answers 503 with code `rate_limited` and no `resetAt`, and the workspace offers a retry, because trying again in a minute is honest advice. A spent allowance answers 429 with `resetAt`, and the workspace offers no retry, because a retry would only be refused. Absent credentials allow the extraction and log loudly. Anyone changing one has to keep the three distinguishable.

- **`session_cap_reached` is a code that is never a response.** It sits in `EXTRACTION_ERROR_CODES` so the workspace's copy table stays exhaustive and TypeScript finds a missing case, but the app refuses before it sends, so the route never returns it. Adding a code to that union breaks `npm run build` until the copy table catches up, which is working as intended.

- **The samples are committed and regenerable.** `public/samples/` holds the three fictional receipts, about 60 KB each, and `scripts/make-sample-receipts.mjs` rebuilds them from SVG through the `sharp` already in `node_modules`. They are not gitignored, unlike the `.playwright-mcp/` fixtures, so keep them small and keep the generator beside them rather than letting three binaries become a mystery.

- **A Mantine compound member is undefined inside a server component.** `Table.Thead` and `List.Item` are static properties hung off a client component, which crosses the server boundary as a reference rather than as the function object, so a server component rendering them gets a 500 with no useful message. `app/about/page.tsx` imports `TableThead`, `TableTd`, `ListItem` and their siblings by their own flat names for that reason. Anyone adding a Mantine table to a server component will hit the same wall.

- **`lib/project-facts.ts` imports `lib/extract-receipt.ts`, which pulls in the OpenAI SDK.** Every component that reads the figures is therefore a server component and has to stay one: `StepCards`, `StatTiles`, `ActionBand` and the About page. `Screenshots` is the one client component on the landing page and deliberately imports no figures.

- **The app has a file picker, not a drop zone.** `@mantine/dropzone` is not a dependency and `components/ReceiptWorkspace.tsx` renders a Mantine `FileInput`. The product spec and the portfolio baseline both say drop zone, which is a statement of intent a later change could satisfy rather than a description of what ships today. The README says file picker, because it describes what is there.

- **Mantine writes a stored colour scheme even under `defaultColorScheme="auto"`.** A visitor who never touches the toggle still ends up with a value in `localStorage` after one visit. That is Mantine's own behaviour, not something this repo added, and it is worth knowing before anyone debugs why a system theme change stopped following.

- **The screenshots and the samples both enter git, and both have a generator.** `scripts/capture-screenshots.mjs` retakes `public/screenshots/` and needs Playwright, which is not a project dependency: it was installed with `npm i --no-save playwright` so `package.json` stayed clean, and a later `npm ci` drops it. The script says so at the top. Retake the captures whenever the page changes, which slice 9 will need to do.

- **Scaffold into this directory without destroying it.** `ai-receipt-scanner-spec.md`, `handoff.md` and `tasks.md` are the only files here and they are the whole record of the project, so losing them loses everything decided so far. `create-next-app` refuses to scaffold over conflicting files but is happy alongside non-conflicting ones, and those three conflict with nothing it writes, so `npx create-next-app@latest . --ts` in place is safe. Check `git status` after it runs and confirm all three are still there and unmodified. If any tool wants to empty the directory first, scaffold into a sibling temp directory and copy the generated files in instead.

## 10. Working style

Nothing in this repo gets deleted, emptied or overwritten to make room for generated code. Commit before any scaffold or codemod, and when a tool wants a clean directory, generate elsewhere and copy in. Ask before removing a file Bob has not asked to remove.

The writing rules in `~/.claude/CLAUDE.md` apply to every piece of prose here and in the repo: no em dashes, no negate-then-assert reversals, active voice with a named actor, and no AI attribution in commit messages or PR bodies.
